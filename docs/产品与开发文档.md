## 1. 文档目的

本文档定义「微文档」从产品定位、功能规格、技术方案、数据模型、接口、安全、部署到验收与排期的完整交付标准。研发、测试、运维均以此为单一事实来源（SSOT）。

## 2. 产品定位

### 2.1 一句话

部署到自己服务器后，在浏览器中登录，以「左侧目录树 + 右侧内容区」管理笔记与办公文件：支持新增、修改、预览；覆盖 Markdown / Word / Excel / PPT / PDF 等格式。

### 2.2 对标体验

| 维度 | 对标 | 本产品取舍 |
|------|------|------------|
| 布局 | Obsidian / VS Code / 企业微信微文档 | 左树右内容，文件即笔记 |
| 权限 | 企业网盘登录 | **必须鉴权**；首期以个人/小团队账号为主 |
| 协同 | Google Docs / 微文档多人光标 | **不做多人实时协同**；同一文件同一时刻仅一人可编辑 |
| Office | ONLYOFFICE / Collabora | **嵌入 ONLYOFFICE Docs Community**，不自研排版引擎 |
| 笔记 | Typora / Obsidian MD | 自研 MD 编辑器（所见即所得 + 源码双模式） |

### 2.3 明确不做（首期）

- 多人实时协同编辑（OT/CRDT）
- 音视频会议、即时聊天
- 移动端原生 App（可用响应式 Web）
- 邮件系统、日历、看板等外围办公套件
- 自研 Word/Excel/PPT 渲染与编辑内核

### 2.4 成功标准（上线验收）

1. Windows 与 Linux 均可按文档一键/半小时内部署成功。  
2. 未登录无法访问任何文件内容与下载链接。  
3. 用户可完成：建目录 → 新建/上传文件 → 编辑 → 预览 → 重命名/移动/删除 → 回收站还原。  
4. `.md` 在系统内流畅编辑与预览；`.docx/.xlsx/.pptx/.pdf` 可在浏览器打开编辑或预览。  
5. 外网通过 HTTPS 域名可稳定使用（含 ONLYOFFICE 回调互通）。

## 3. 用户与场景

### 3.1 用户角色

| 角色 | 说明 | 首期能力 |
|------|------|----------|
| 普通用户 | 自己的笔记与文件空间 | CRUD、预览、编辑、回收站、个人设置 |
| 管理员 | 系统初始化与运维 | 用户管理、存储配额、系统配置、审计查看 |
| 访客 | **首期不做公开匿名访问** | — |

> 设计预留：未来可增加「只读分享链接」。首期可不开放分享，但数据模型预留字段。

### 3.2 核心场景

1. **外出编辑笔记**：手机/笔记本浏览器登录，改 Markdown 会议纪要并自动保存。  
2. **改 Word 合同草稿**：上传/打开 docx，在 ONLYOFFICE 中编辑，关闭后自动回写。  
3. **看 Excel 报表**：只读预览或编辑单元格后保存。  
4. **翻 PDF 资料**：浏览器内预览，支持翻页、缩放、搜索（PDF.js）。  
5. **整理资料库**：拖拽移动文件夹，搜索文件名/笔记正文。

## 5. 功能规格（完整）

### 5.1 账号与鉴权

| ID | 功能 | 规则 |
|----|------|------|
| A-01 | 登录 | 用户名/邮箱 + 密码；失败锁定（如 5 次 / 15 分钟） |
| A-02 | 登出 | 作废 Refresh Token；清除客户端态 |
| A-03 | Access Token | JWT，短有效期（建议 15–30 分钟） |
| A-04 | Refresh Token | HTTP-Only Secure Cookie 或旋转式刷新令牌表；有效期 7–30 天 |
| A-05 | 密码策略 | 最少 8 位；哈希用 Argon2id 或 bcrypt(cost≥12) |
| A-06 | 修改密码 | 校验旧密码；改密后吊销其他会话（可配置） |
| A-07 | 首次安装向导 | 无用户时强制创建管理员；禁止未初始化开放注册 |
| A-08 | 用户管理（Admin） | 启用/禁用、重置密码、配额 |
| A-09 | 会话列表 | 查看登录设备/IP/时间，可踢下线 |
| A-10 | CSRF | Cookie 方案必须防 CSRF；Bearer Header 方案可豁免表单 CSRF |
| A-11 | 可选 2FA | **二期**：TOTP |

**鉴权边界**

- 所有业务 API 默认 RequireAuth。  
- ONLYOFFICE 下载文件 URL、callback URL 使用**独立短期签名 token**（不可用用户长效 JWT 裸奔到公网）。  
- 静态前端可公开；API 与文件流不可公开。

## 6. 技术方案（调研结论）

### 6.1 为什么这样拆

调研结论：

1. **Go + PG + React** 非常适合做「鉴权 + 目录元数据 + 文件流 + 业务壳」。  
2. **不要自研 Office 排版**。业界成熟路径是嵌入 [ONLYOFFICE DocumentServer](https://github.com/ONLYOFFICE/DocumentServer)。  
3. **MD 必须自研前端编辑器**（TipTap/Milkdown），体验才像笔记。  
4. **预览加速（可选）**：业界有「kkFileView 做快预览 + OnlyOffice 做编辑」的组合；首期为降复杂度，**预览也走 OnlyOffice view 模式 + PDF.js**；若预览性能不足，二期加转换缓存服务。  
5. 同类「左树右编辑」产品（Editoro、各类 Notion 自托管）验证了 UX；本产品差异点是**强 Office 文件支持 + 鉴权自托管**。

### 6.2 逻辑架构

```
                    ┌──────────────┐
   Browser          │ React SPA    │
                    └──────┬───────┘
                           │ HTTPS API
                    ┌──────▼───────┐
                    │ Go API Gateway│  鉴权 / RBAC / 限流
                    │ 业务服务      │  目录、文件、搜索、锁
                    └──────┬───────┘
             ┌─────────────┼──────────────┐
             ▼             ▼              ▼
        PostgreSQL     对象/本地磁盘    ONLYOFFICE Docs
        元数据/用户     文件二进制       编辑与预览引擎
```

### 6.3 技术选型（锁定）

| 层级 | 选型 | 说明 |
|------|------|------|
| 前端 | React 18+ + TypeScript + Vite | 路由 React Router |
| UI | Ant Design 或 shadcn/ui | 树、表格、表单成熟 |
| 状态 | Zustand 或 Redux Toolkit | 树与打开文件态 |
| MD 编辑 | TipTap（ProseMirror） | 扩展生态好；存 MD 或 JSON→MD |
| 代码编辑 | CodeMirror 6 | txt/json |
| PDF | pdfjs-dist | 预览 |
| 后端 | Go 1.22+ | chi / gin / echo 任选其一并锁定 |
| ORM | sqlc 或 ent 或 GORM | **推荐 sqlc**（类型安全） |
| DB | PostgreSQL 16 | |
| 迁移 | golang-migrate / goose | |
| 认证 | JWT + Refresh Token 表 | |
| 文件存储 | 本地目录（默认）+ 可切换 S3/MinIO | 接口抽象 `Storage` |
| Office | ONLYOFFICE Docs Community (Docker) | AGPL 需合规注意 |
| 反向代理 | Caddy 或 Nginx | HTTPS |
| 部署 | Docker Compose（主）+ 原生二进制（Win 无 Docker 时的降级说明） | |

### 6.4 跨平台部署策略

| 环境 | 推荐方式 |
|------|----------|
| Linux 服务器 | Docker Compose：`app` + `postgres` + `onlyoffice` + `caddy` |
| Windows Server | Docker Desktop / WSL2 跑同一套 Compose **优先** |
| Windows 无 Docker | Go 二进制 + 安装版 PostgreSQL；OnlyOffice 仍强烈建议容器或 Linux 旁路机；文档中写明限制 |
| 开发机 | `make dev`：API hot reload + Vite + 本地 PG |

> 产品原则：**一套代码，配置区分 OS**；路径使用 `path/filepath`，存储根目录可配。

### 6.5 关键设计要点

1. 密码哈希不可逆；密钥进环境变量。  
2. 文件下载鉴权；禁止 `../` 路径穿越；存储 key 用 UUID，不暴露真实磁盘路径。  
3. OnlyOffice JWT 双向校验。  
4. 上传 MIME/扩展名双检；病毒扫描列为二期。  
5. 限流：登录、上传、搜索。  
6. 安全头：HTTPS、HSTS、CSP（OnlyOffice iframe 需仔细配置 frame-src）。  
7. 备份：每日 PG dump + 文件目录增量。

## 7. 数据模型

### 7.1 ER 概要

- `users` 1—N `workspaces`（或 N—N `workspace_members` 预留）  
- `workspaces` 1—N `nodes`（目录树，邻接表或物化路径）  
- `nodes` 1—1 `file_blobs`（文件夹无 blob）  
- `nodes` 1—N `file_versions`  
- `nodes` 0—1 `edit_locks`  
- `users` 1—N `sessions` / `refresh_tokens`  
- `audit_logs`

## 12. 部署架构

### 12.1 推荐生产拓扑

```
Internet
   │
   ▼
Caddy/Nginx (TLS)
   ├─ /            → 静态前端
   ├─ /api         → Go API
   └─ office.xxx   → ONLYOFFICE DocumentServer
PostgreSQL、文件卷 持久化
```

### 12.2 Docker Compose 服务清单

1. `postgres`  
2. `api`（Go）  
3. `web`（Nginx 托管 SPA，或由 api 托管静态资源）  
4. `onlyoffice/documentserver`  
5. `caddy`（可选合一入口）

### 12.3 联通性验收清单（必须全绿）

- [ ] 浏览器能打开 `PUBLIC_BASE_URL`  
- [ ] 浏览器能打开 `ONLYOFFICE_URL` 的 `/healthcheck`  
- [ ] OnlyOffice 容器能 GET 到 `PUBLIC_BASE_URL/api/.../office/content/...`  
- [ ] Go 能接收 OnlyOffice POST callback  
- [ ] 保存后磁盘文件 hash 变化，再次打开内容为新版本  

### 12.4 Windows 专项

- 优先 Docker Desktop。  
- 数据目录挂载注意权限与路径（`D:\微文档-data`）。  
- 防火墙放行 80/443。  
- 若无法跑 OnlyOffice：系统仍可完整使用 MD/TXT/PDF 预览；Office 编辑入口显示「未配置文档服务」。

## 17. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| OnlyOffice 三方网络不通 | Office 无法打开/保存 | 部署手册强制检查清单；提供诊断页 |
| OnlyOffice 内存占用高 | 小机器 OOM | 文档标明内存；限制同时编辑数 |
| AGPL 合规 | 商业分发风险 | 架构上进程隔离；商用评估正式授权 |
| 中文搜索质量 | 搜不准 | `pg_trgm` + 后续分词组件 |
| Windows 无 Docker | Office 难部署 | 降级 MD/PDF；或旁路 Linux 容器主机 |
| 大文件上传 | 失败/超时 | 分片上传（二期）；首期限制大小 |

## 19. 产品决策汇总（冻结）

1. **定位**：个人/小团队自托管「笔记式文件柜」，不是协同办公套件。  
2. **布局**：左目录树，右内容；深链可恢复。  
3. **鉴权**：强制登录；安装向导建管理员。  
4. **MD**：自研编辑器，自动保存。  
5. **Office/PDF**：ONLYOFFICE；PDF 额外 PDF.js 预览。  
6. **协同**：不做多人实时编辑；做编辑租约锁。  
7. **技术栈**：Go + PostgreSQL + React，Win/Linux 以 Docker Compose 为主路径。  
8. **目标**：完整可上线产品，按本里程碑交付，不交付半截 Demo。
